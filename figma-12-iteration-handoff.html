12 / Iteration & handoff

Repair the owner.
Then gate the regression.

Actual repository QA history · not invented findings

The final frame uses real ATELIER remediation history: destructive media crops and contrast/state regressions were fixed at shared owners, then protected with rendered regression checks.

Before / visual regression

Cover crops damaged garment evidence.

Primary editorial media used aggressive object-fit: cover and focal assumptions. Shared captions/button states also risked low contrast on variable surfaces.

→
After / root-cause repair

Contain by default; verify any cover crop.

Home, House, Services and editorial media owners moved toward contain/top-safe behavior, with explicit background ownership and regression checks for unverified cover crops and visible text states.

Before / CTA specificity

Checkout button contrast was overridden by broad ledger selectors.

A shared selector applied inverse button styling too broadly, creating a state-specific contrast regression.

→
After / scoped owner

Specificity narrowed to the owning summary component.

The selector was scoped to .order-summary-card .btn-checkout, preserving intended contrast without changing unrelated ledger actions.

Tokens

Semantic, not decorative

Use neutral primitives, state roles, 0px radius and shared spacing/motion tokens. Do not create one-off colour accents.

Media

Protect purchase evidence

Full-garment/focal integrity outranks cinematic cropping. Cover requires a verified focal contract.

Responsive

Recompose priorities

Mobile preserves identity → price → variant → size → purchase → reassurance rather than shrinking desktop.

States

Never colour-only

Focus, selected, unavailable, error and success use text/boundary/state structure as well as semantic colour.

Motion

Hierarchy or feedback only

Reduced motion keeps the same information and completion path. No scroll-jacking or motion-only meaning.

System reality

Prototype truth stays visible

Local persistence may be called saved; payment, fulfilment, email and live inventory/auth must not be described as connected.

Cloud gate

V15 QA covers production build, route resolution, broken media, representative 1440/1280/768/390/320 states, overflow, runtime errors, serious/critical Axe findings and key interactions.

Evidence boundary

Automated QA is regression evidence, not complete accessibility certification or participant usability proof.

Planned validation

Participant tasks are defined separately for find → size/fit → service information → Bag → checkout. No participant results are fabricated in this case study.
