# ATELIER — Visual Regression Plan

## Purpose

Protect the approved editorial commerce system from visual regressions across repeated human/AI changes. Rendered pixels and inspected states are evidence; source/build success alone is not a visual pass.

## Active V14 source of truth

1. `docs/uiux/Design-Contract-V14.md`
2. `docs/uiux/V14-Remediation-Contrast-Media.md`
3. V14 implementation owner: `atelier-v14-site.css` → `atelier-v14.css` → inherited V13 foundation
4. Representative rendered captures generated by `.github/workflows/final-visual-qa.yml`
5. Static/local/simulated commerce reality recorded in the V14 Design Contract

## V14 automated gates

### Whole-site structural/reality gate

`scripts/v14-whole-site-qa.mjs` blocks on material issues including:

- non-200 route response;
- browser console/page errors;
- wrong/missing V14 style owner;
- horizontal overflow;
- broken rendered images;
- missing/duplicate primary H1;
- missing visible nav;
- missing seeded Bag/Saved/Checkout/Order state;
- weakened Checkout/Auth/Contact reality disclosure;
- sticky-nav anchor collision on House.

### Visual sanity gate

`scripts/v14-visual-sanity-regression.mjs` exists because earlier V14 QA could report zero automated blockers while obvious rendered defects remained.

It must fail when:

- representative footer text/links/actions fall below the defined computed foreground/background contrast threshold;
- a visible shared button label falls below contrast threshold in default, hover or focus state;
- Home campaign media stops using the approved cover treatment;
- Home hero focal Y is no longer top-safe, risking another clipped face/head;
- a state cannot be meaningfully inspected by the regression routine.

The sanity gate also captures explicit evidence for Home hero, footer, secondary CTA default/hover and footer CTA hover.

## Human visual review order

Automation is not permission to skip inspection. Before a substantial V14 remediation can PASS:

1. Open the Home hero capture and verify the model's head/face and primary garment are not accidentally clipped at the declared viewport.
2. Open footer captures and verify content is immediately readable without text selection.
3. Open default/hover button captures and verify the label remains visible while state change is visually clear.
4. Inspect the cross-page V14 screenshot set/contact sheet for hierarchy, page-role drift and obvious color/cascade failures.
5. Inspect desktop pressure captures for crop, overlap, wrapping and visual-density failures.

A screenshot artifact that exists but has not been opened/inspected is `UNVERIFIED`, not PASS.

## Regression debt / lessons

### VR-01 — Responsive media existence

Earlier process miss: Home referenced non-existent responsive collection images. Permanent lesson: prime/render actual media and fail broken resources.

### VR-02 — Hidden state must remain hidden

Earlier process miss: author CSS exposed `[hidden]` promo/variant states. Permanent lesson: inspect state reality rather than source intent.

### VR-03 — Sticky conversion timing

Earlier process miss: mobile PDP sticky CTA appeared at the wrong time. This remains historical coverage; mobile is outside V14 scope.

### VR-04 — Product-card interaction semantics

Earlier process miss: nested card/link semantics were duplicated. Permanent lesson: preserve native interaction ownership.

### VR-05 — Footer surface/foreground cascade mismatch

**Observed V14 failure:** `atelier-v14.css` defined a dark footer with campaign-light foreground. The later whole-site layer changed the footer surface to `--paper` but did not reset inherited foreground roles, producing near-white text on a near-white surface.

**Permanent gate:** a shared surface change must carry its semantic foreground/border/state role with it; V14 sanity regression checks actual computed footer contrast across all root routes.

### VR-06 — Button hover label disappearance

**Observed V14 failure:** a light outlined action could transition to a white label while the rendered surface remained light, making the action label disappear.

**Permanent gate:** shared action variants are checked in default, hover and focus state, not only static screenshots.

### VR-07 — Hero focal point violation

**Observed V14 failure:** Home used `object-fit: cover` with `object-position: center 20%`, visibly clipping the model's head despite the V14 media contract requiring face + garment integrity.

**Permanent gate:** Home hero focal position is asserted and the actual hero capture must be manually inspected at contract desktop widths.

## Baseline update rule

A new screenshot is not automatically accepted. Update visual evidence only when the change is intentional, tied to the current Design Contract or an approved remediation, and manually inspected at the declared project viewports/states.

## Accessibility scope

Contrast/state regression is an accessibility-relevant visual gate, but it does **not** establish formal WCAG conformance. A dedicated accessibility conformance evaluation is required for that claim.
