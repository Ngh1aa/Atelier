# ATELIER — Visual Regression Plan

## Purpose

Protect the approved white editorial commerce system from visual regressions after Prompt 3 remediation. This plan follows the project Design Contract and the `visual-regression-and-design-drift` skill: rendered screenshots are evidence; source/build success alone is not a visual pass.

## Source of truth

1. `docs/DESIGN-CONTRACT.md`
2. The approved white editorial implementation on `main`
3. Representative rendered captures generated by `.github/workflows/final-visual-qa.yml`
4. The local/static/simulated commerce reality documented in `docs/PROMPT2-IMPLEMENTATION-V6.md`

## Stable capture conditions

- Chromium via Playwright.
- Fixed viewport and DPR 1.
- Light color scheme.
- Reduced motion enabled.
- Fonts awaited before capture.
- Animations/transitions reduced for stable evidence.
- Cart and Saved localStorage seeded with deterministic local prototype data.
- Lazy media primed by controlled scrolling before full-page capture.

## Automated blocker candidates

`scripts/final-visual-qa.mjs` records and fails when representative pages show:

- non-200 route response;
- browser console or page errors;
- horizontal overflow;
- missing/duplicate H1;
- unlabeled form controls;
- empty buttons;
- Home product cards regressing to nested `role="link"` semantics;
- broken rendered images after lazy-load priming;
- a `[hidden]` element that remains visibly laid out;
- inactive `ATELIER10` promo state becoming visible;
- Bag variant editor visible before the user opens it;
- mobile PDP sticky purchase CTA visible at the initial top state.

These checks are regression signals, not a substitute for human visual inspection.

## Human visual review order

1. Cross-page top contact sheet: page purpose and composition diversity.
2. 5-second hierarchy and first visual anchor.
3. Logo/nav/CTA readability across top/scrolled/mobile contexts.
4. Mobile recomposition and fixed/sticky overlap.
5. Product/media crop and sharpness.
6. Forms, drawers and visible interaction states.
7. Typography, spacing and micro-polish.

## Regression debt added from Prompt 3

### VR-01 — Responsive media existence

**Process miss:** Home referenced non-existent `-v2-512` collection images. Desktop looked correct while mobile/tablet rendered broken images.

**Permanent gate:** prime lazy media and fail on rendered images with `naturalWidth === 0` or console resource errors.

### VR-02 — Hidden state must remain hidden

**Process miss:** author layout CSS caused elements carrying `hidden` to render, exposing inactive promo and Bag variant controls.

**Permanent gate:** fail when a `[hidden]` element has a visible layout box; also explicitly assert the Bag editor and inactive promo are absent from the default rendered state.

### VR-03 — Sticky conversion timing

**Process miss:** PDP sticky Add to Bag appeared whenever the primary button was outside the viewport, including before the user had reached it, obscuring product information at the first fold.

**Permanent gate:** assert the sticky purchase bar is not visible at mobile top and capture a separate state after passing the primary action.

### VR-04 — Product-card interaction semantics

**Process miss:** Home product cards contained real anchors/buttons while JavaScript also made the card container keyboard-link interactive.

**Permanent gate:** fail if `.product-card[role="link"]` reappears.

## Baseline update rule

A new screenshot is not automatically accepted. Update the baseline/evidence only when the visual change is intentional, tied to the Design Contract or an approved remediation, and has been inspected at representative desktop/mobile widths.

## Accessibility scope

The workflow performs a focused rendered smoke check for labels, headings, overflow and visible interaction state. It does **not** claim formal WCAG conformance; a dedicated accessibility conformance evaluation is required for that claim.
